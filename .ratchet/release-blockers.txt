# Release blockers: tests whose absence means the product is broken, whatever else is green.
# One test name per line. Everything after a `#` is a comment.
#
# Why this file exists: `cargo test <name>` filters by substring and exits 0 when the filter
# matches nothing. A curated list of release-blocking tests is therefore worthless on its own,
# because renaming or deleting a test leaves every command that named it reporting success while
# running nothing. `xtask verify-tests` asks cargo which tests exist and fails when a name here
# is not among them.
#
# Check the list:  cargo run -p xtask -- verify-tests .ratchet/release-blockers.txt
# Matching:        substring, exactly as `cargo test <name>` matches.
#
# Editing this file is legitimate when a test is deliberately renamed, split or replaced: name
# the test that took over the responsibility. Deleting a line because the check is failing is
# not: the guard is telling you the responsibility is now uncovered.
#
# What this guard does NOT prove:
#   * that these tests PASS. It only proves they exist. `cargo test --workspace` proves the rest.
#   * that the list is COMPLETE. No tool can decide that; it is a judgement, written down here so
#     that it can be held to account.
#   * anything about a test behind a feature flag that is off, or a target not built on this
#     platform: such a test is not listed by cargo and so counts as missing.
