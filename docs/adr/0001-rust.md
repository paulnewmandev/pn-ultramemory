# ADR-0001: Build in Rust

**Status:** Accepted

## Context

The tool is installed on developers' machines, is started by hooks on many tool calls, and indexes
large repositories. It has to start in milliseconds, stay small, run without a language runtime,
and be trustworthy about memory safety because it parses untrusted repositories. It also has to be
approachable enough that other people will fork it and send changes.

## Decision

Write the core, the command line, the MCP server and the hooks in **Rust (edition 2024)**, in one
static binary. The compiler is pinned in `rust-toolchain.toml`. Declarative parts use SQL for the
schema, tree-sitter queries and TOML for language packs, and POSIX shell for the installer and
project scripts.

## Consequences

- One small binary with no runtime for users to install, and fast start-up for hooks.
- Memory safety for parsing untrusted input, and `unsafe` code is forbidden by default.
- A mature tree-sitter ecosystem and a large pool of potential contributors.
- Contributors need Rust. Declarative language packs keep the barrier low for the most common
  contribution, which is adding a language.
- Compile times are longer than in interpreted languages.

## Alternatives considered

| Option | Why not |
|---|---|
| C | Fast and small, but memory-unsafe on hostile input, and a smaller pool of contributors. |
| Go | Easy to contribute to, but linking tree-sitter needs cgo, which weakens the single static binary. |
| Zig | Promising, but the ecosystem is still young. |
| TypeScript or Python | A runtime to install, slower start-up for hooks, and a heavier footprint. |
